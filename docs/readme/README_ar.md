# dsh-pi-bridge

إضافة واحدة، مضيفَان. تُثبَّت في pi فتتيح لـ pi استخدام إضافات DeepSeek Harness، وتُثبَّت في DSH فتتيح لـ DSH استخدام إضافات pi. لا تقوم أيٌّ من الجهتين بتنفيذ كود الطرف الآخر بـ"ترجمته": الإضافة تعمل دائمًا داخل مضيفها الأصلي — حيث إن API المضيف حقيقية — والجهة الأخرى لا تفعل سوى تمرير الاستدعاءات.

```text
# pi
pi install npm:dsh-pi-bridge            # أو: pi install git:github.com/Twofruitsgrape/dsh-pi-bridge

# DSH
dsh plugin --profile <name> install github:Twofruitsgrape/dsh-pi-bridge
```

أعد تشغيل المضيف بعد التثبيت. كلتا الكلمتين المفتاحيتين (`pi-package` و `dsh-plugin`) معلنتان، لذا يجد متجر كلِّ منظومة هذه الحزمة.

## ما تحصل عليه في كل مضيف

| | pi | DSH |
|---|---|---|
| استخدام إضافات الجهة الأخرى | `dsh_install`، `dsh_preview`، `/dsh-install`، `/dsh-preview` | `pi_install`، `pi_preview` |
| إدارة ما تم جسره | `/bridge-list`، `/bridge-remove` | `bridge_list`، `bridge_remove`، `bridge_status` |
| مهارة Skill | `skills/dsh-pi-bridge/SKILL.md` | نفس `SKILL.md`، مركّبة عبر سجل المهارات |

تستعمل الجهتان واحدة الصياغة للمصادر: `npm:<pkg>[@ver]`، `git:github.com/<owner>/<repo>[@ref]`، `github:<owner>/<repo>`، رابط المستودع أو مسار محلي — نفس الأنماط التي يقبلها كل مضيف أصلًا.

مقتطف من جلسة حقيقية، حرفيًا: إقلاع DSH حقيقي، نموذج حقيقي، تثبيت حزمة pi منشورة فعلًا.

```text
dsh> pi_install({ source: "npm:pi-web-access", prefix: "web" })
  bridged npm:pi-web-access as pi-web-access@0.41.0
    mode: package code runs natively inside a supervised pi process
    tools: web_web_search, web_source_check, web_fetch_content,
           web_get_search_content, web_web_enable
    pi slash commands registered in pi: /websearch, /curator, /google-account, /search

dsh> web_web_search({ query: "DeepSeek V4" })   # أداة جاءت من حزمة pi
  -> نتائج بحث حية، جُمعت بواسطة provider الحزمة نفسها بإعداداتها
```

## كيف يعمل

### إضافات pi تدخل DSH: عملية pi خاضعة للإشراف

يقوم `pi_install` بتتجسيد الحزمة في ذاكرة الجسر المؤقتة، فيثبّت تبعياتها الحقيقية، ثم يحمّلها داخل عملية pi (`pi --mode rpc`) يشرف عليها الجسر. كل بند يورده pi يصبح أداةً واحدة في DSH، والاستدعاءات تمرَّر إلى pi وتعيد النتيجة التي حسبها pi. يُركَّب مجلد `SKILL.md` بوصفه بيانات عبر `ctx.skills`. ترى الحزمة `registerTool` الحقيقية لـ pi و`registerProvider` وسجل النماذج وبيانات اعتماد providers الحقيقية — الحزمة التي تلمس الشبكة أو النماذج تتصرف كما تتشعب في يد مستخدم pi بدقة.

هذا التصميم حلّّ محل النهج السابق: إعادة تشغيل تسجيلات في DSH والاتكاء على استيرادات مدسوسة بوصفات وهمية (stubs). تلك النسخة نجحت في كل اختبارات التمثيل وانهارت أمام الحزم الحقيقية — لأن استيرادًا مُدسوسًا هو أداة لا تعمل. التمرير إلى المضيف الأصيل هو الشكل الوحيد القادر على البقاء صادقًا مع النتائج.

### إضافات DSH تدخل pi: جلسة DSH حية

يطلب حزمة DSH المُجمَّعة (bundle) `ctx.tools` و`ctx.llm` حقيقية وسجل مهارات، لذا يطلب `dsh_install` من جلسة DSH الحية أن تحمّله هي بنفسها. العائق هنا: الحزمة المثبتة بواسطة مدير الإضافات هي وصل رمزي (symlink) تحت `node_modules` للملف الشخصي، والمحددات العارية `@deepseek-ai/*` لا تُعالج — والقياس أبلغ عن `MODULE_NOT_FOUND`. يؤدي `src/dsh-loader.js` هذا بالضبط: يعيد كتابة هذه المحددات إلى روابط URL للوحدات التي يحملها الإصدار الجاري تشغيله (حزم حقيقية، لا وصفات وهمية)؛ أما الاستيرادات النسبية و`node:` واستيرادات الأطراف الثالثة فتبقى كما هي. يذهب المجمّع ليُسجّل لدى المضيف، ويصل pi أداة واحدة مُمرَّرة لكل قدرة.

نقطة النهاية مغلقة افتراضيًّا؛ إقلاع DSH عادي لا يفتح منفذًا واحدًا أيًّا:

```bash
DSH_PI_BRIDGE_DSH_SERVE=43191 dsh ...                    # جانب DSH
DSH_PI_BRIDGE_DSH_ENDPOINT=127.0.0.1:43191 pi ...        # جانب pi
```

يُربط إلى 127.0.0.1 حصرًا، ويرفض العميل العناوين غير الدائرية (غير loopback). حين يتعذر بلوغ جلسة DSH حية، يقول `dsh_install` ذلك بصدق ويرجع إلى نمط الترجمة، بدل أن يمثل أن التمرير نجح.

### حين يكون كلا المضيفين بعيدين عن المنال

ما زال الجسر يحلّ المصدر، ويترجم TypeScript (`stripTypeScriptTypes` من `node:module` دون تنزيل سلسلة أدوات)، ويحقق ما تسجله الحزمة، لذا يعمل `preview` في كل مكان. إعادة تشغيل التسجيلات في المضيف الآخر تُترك لسيناريوهات المضيف الواحد وللحزم المجمّعة التي حمولتها بأكملها بيانات — مجلّ DSH على هيئة مجلد مهارات صرف لا يوجد فيه ما يُستدعى، لكن المهارة نفسها تعبر. يطبق كلا المضيفين [مواصفة Agent Skills](https://agentskills.io/specification).

### أشكال المعاملات والنتائج

حمل أدوات DSH جدول مواصفات الخصائص (`{ text: { type: "string", required: true } }`) الذي يترجمه `@deepseek-ai/dsh-tools` إلى JSON Schema؛ وحمل أدوات pi تحمل JSON Schema مباشرة (TypeBox). يجري `src/schema.js` التحويل في الاتجاهين، وتنقض النتائج عبر الإسقاط نفسه: `{ content: [{ type: "text" }] }` الخاص بـ pi و`{ ok, result }` الخاص بـ DSH يترجمان بعضهما. يتحقق المضيف من المخططات وقت التسجيل، والجزء الجزئي الذي يقبلوه ضيق عن مسودة JSON Schema — علامة `required` على عقدة خاصية، أو مصفوفة `required` بمستوى الكائن في مخطط المخرجات، تُسقط فعل تنشيط الإضافة كلها. هذه القواعد واردة من قياسات على المضيفين المثبتين؛ حمل الاختبارات يحملها كعبارة تأكيد.

## مُثبت — وكيف

كل بند أدناه قيست مقابل مضيفين حقيقيين، لا مقابل تمثيلات:

- إقلاع DSH حقيقي، نموذج حقيقي، تثبيت `npm:pi-web-access` واستدعاء `web_web_search` عبره (النتائج يجمعها provider الحزمة نفسها)
- جلسة DSH حقيقية تحمّل مجمّعًا باستيراد عارٍ لـ `@deepseek-ai/dsh-tools`، ثم عملية مستقلة تستدعي أدواته عبر loopback
- هذا الجسر يشغّل مدخل DSH الذاتي بنفس الآلية التي يصطدم بها مجمّع أجنبي داخل pi

كل واحد منها وضبط خللًا لا يضبطه تمثيل ولو واحد: ملفًا نسيه المانيفست المنشور؛ مخطط مخرجات يرفضه المضيف فيظل الإضافة عاطلة بصمت؛ `process.execPath` يشير في عملية المضيف إلى التطبيق لا إلى node؛ إبلاغ صفرِ قدرة عند إعادة التثبيت لأن الخادم الخفي حمّل الحزمة من قبل؛ سياقًا (scope) يمنع إسناد الخصائص؛ معالج خادم يجري خارج الليف الذي يُهيّج الخدمة؛ مضيف يرفض تكرار أسماء الأدوات.

```bash
npm test                # كل حزم الاختبار دون اتصال
npm run test:offline    # الأنبوب + مدخلَي المضيفين للجهتين
npm run test:proxy      # الخادم الخفي، التمرير جانب DSH وجانب pi
npm run test:host       # مقابل إصدار DSH المثبت (انظر الملاحظة)
npm run test:network    # حزم منشورة حقيقية من npm وGitHub
npm run test:live       # ما سبق مقابل pi يعمل فعلًا
```

يقرأ `test:host` من الداخل ما في asar المضيف المثبت — من `@deepseek-ai/dsh-tools` المضيف نفسه— ولا يقرؤه إلا بنظام ملفات يخترقه بواقة Electron؛ شغّله داخل عملية المضيف. تحت node العادي يبلّغ SKIP تصريحًا، بلا تلويح بأن المضيف رفضنا.

تُبنى مركبات الاختبار أيديًا في الحزم دون اتصال: امتداد pi بلغة TypeScript عبر منشئ TypeBox، مجمّع DSH عبر `defineTool`، مجمّع باستيراد عارٍ لحزمة المضيف — ثم يساق الأنبوب كله مقابل تمثيلات مسجَّلة، وتُشغَّل الأدوات التي تخرج من الجسر حقًا. بعض القواعد تسكن عبارات تأكيد ساكنة لأنها لا تُمثّ ذاتها إلا عند إقلاع حقيقي: أشكال المخططات التي يقبلها المضيف؛ الملفات الواجب نشرها؛ كون المجمّع الخاضع للتحليل ينبغي ألا يبيت عمليات ولا يحكم المنافذ.

## ما الذي لا يعبر

يبلّغ الجسر هذه الحالات بصدق، فلا يفشل في صمت:

- **واجهة المضيف**: صفحات المتصفح في DSH / `ctx.slots`؛ مُرسم TUI في pi، و`ctx.ui`، ومفاتيح مختصرة، وأعلام سطر الأوامر.
- **مُهايئات النماذج المسجَّلة لدى المضيف**: من يضيف provider ف يفعله تجاه مضيفه الأصلي — وهذا عينا معنى "عدم الترجمة" — فتسقط providers الخاصة بـ pi في pi، وتسقط adapter الخاصة بـ DSH في DSH.
- **مجمّعات DSH بلا ما يُستدعى**: طبقة سطحية صرف يحملها واجهة أو إعدادات لا يوجد فيها أدوات لتمريرها. يقول preview ذلك تصريحًا بدل استجناء قدرات.
- **حزم تستلزم مضيفًا تفاعليًّا**: الاستدعاء الممرَّر يمكن أن يُسيل التقدم، بل لا يمكنه أن يفجّر منتقيًا في الجهة الأخرى.

## الصمود

تنقض التسجيلات في الجلسة الجارية فورًا. يقرأ كلُّ مضيف عند تحميل الإضافة من `~/.dsh-pi-bridge/bridges.json` ما دوَّنه بنفسه، فيعيش التثبيت فوق إعادة التشغيل — وقد تحقق من ذلك بإعادة تشغيل جلسة DSH وإيجاد أدوات الجسر في مكانها. تشمل أعادة القراءة ذاكرة مؤقتة فحسب: إقلاع المضيف لا ينتظر تنزيلًا شبكيًا أبدًا؛ وإذا فُرغت الذاكرة أبلغ الجسر عن عدم الجاهزية بدل التعلّق. يفعل إعادة التشغيل أيضًا بأن تصبح الأدوات الجديدة مرئية لعملاء آخرين (واجهة الويب، النافذة الثانية) لأن مازجهم قائمة الأدوات عند الإقلاع. يُعطَّل بالإعداد `restoreOnLoad: false` في تكوين المجمّع.

لا نكتب في إعدادات أي مضيف. ينسى `bridge_remove` جسرًا ويمحو مجلد بنائه؛ الأدوات المسجلة لدى العملية الجاريةAlready تصمد حتى إعادة التشغيل، لأن تسجيل إلغاء صامت لحالة المضيف أردأ من إبقائها مرئية.

## الأمان

الحزمة المجرورة **تنفذ شيفرة بصلاحياتك، في المضيف حيث تشتغل**. يحدد كل مضيف إضافات المطلب نفسه؛ هذه الحزمة جاءت من منظومة أخرى ولم تمرّاب طقس المراجعة لمتجرها، فيصح المطلب المزيد. اقرأ كودها المصدر أولًا؛ فالـ preview يفكك ويفحص فقط، ولا يسجّل شيئًا.

التمرير ليس صندوق رمل: تنفذ الحزمة بثقة مضيفها الأصلي الكاملة، لأن ذلك سبب نجاحها. تتسلسل نقطة النهاية الدائرية مع 127.0.0.1 وحدها، ولا تفتح إلا إذا ضُبط `DSH_PI_BRIDGE_DSH_SERVE`، ويرفض العميل العناوين غير الدائرية. أي أحد يلحق بذلك المنفذ قادر على استدعاء كل أداة حمّلتها الجلسة. افتح المنفذ عند الحاجة فقط.

## المشهد

```text
index.js                مدخل DSH: name / inject / apply(ctx)، أي أدوات pi_*
extensions/index.js     مدخل pi: مصنع default(pi)، أدوات وأوامر dsh_*
skills/dsh-pi-bridge/   SKILL.md، يستعمله المضيفان معًا
cordis.patch.yml        تركيب مجمّع DSH (حكمة المفتاح في لوحة الإضافات)
daemon/run.mjs          عملية pi الخاضعة للإشراف؛ واجهة loopback لأدواتها
daemon/bootstrap.js     يُحمَّم بواسطة مُحمّل الامتدادات الحقيقي الخاص بـ pi، داخل pi
src/proxy.js            جانب DSH: تشغيل/إعادة استخدام الخادم الخفي، وتمرير الاستدعاءات
src/dsh-loader.js       جانب DSH: تحميل المجمّع وقت التشغيل مقابل scope حي
src/serve.js            جانب DSH: نقطة نهاية loopback للمضيف الآخر
src/dsh-host-client.js  جانب pi: محادثة الجلسة DSH الحية
src/resolve.js          مصادر npm / git / url / محلية إلى الذاكرة المؤقتة، مع تثبيت التبعيات
src/load.js             بناء الشجرة المرآة، وترجم TypeScript، وتثبيت التبعيات الحقيقية
src/manifest.js         كشف المضيف من الكلمات المفتاحية والمانيفست وهيئة المجلد
src/capture.js          مضيفون ممثلون مسجلون للملاذدين اتفاقيَّ المدخل
src/schema.js           تحويل مخططات المعاملات في الاتجاهين
src/capabilities.js     نموذج قدرات معايَر؛ إسقاطٌ عال النتائج
src/replay-dsh.js       capabilities -> ctx.tools / commands / skills
src/replay-pi.js        capabilities -> pi.registerTool / registerCommand
src/restore.js          إعادة قراءة الجسور المدونة عند إقلاع المضيف
src/stubs.js            مسح الاستيرادات وتوليد وصفات وهمية للـ preview
src/tar.js              قارئ gzipped-tar، بلا تبعيات
src/transpile.js        TypeScript -> ESM، عبر node:module
```

الـ `index.js` لا يستورد سوى أدوات `node:` المدمجة زائد الحزمة نفسها، ويصرّح بـ `inject: ["tools"]` — الخدمة الوحيدة في يحتاجها. المهارات والإعدادات تُلمس عبر `ctx.inject` بعد فحص القدرة؛ الملف الشخصي الذي لا يضم سجل مهارات لا يركّب المهارة فحسب، بدل أسقاطه إقلاعُه.
